# Data Collection Pipeline

## Overview

Multi-camera RTSP data collection for security camera training data:
- **YOLO detection** — person/car detection with configurable hysteresis trigger
- **High-quality video** — saves clips at native camera resolution for human labeling
- **ROI filtering** — optional polygon zones to ignore irrelevant areas (sidewalks, roads)
- **YOLO weak labels** — exports sampled frames + `.txt` label files for training

---

## Quick Start (one command)

```bash
./home_guard_project/data_collection/start.sh
```

That's it. The script automatically:
1. Checks Python >= 3.12 and installs `uv` if needed
2. Installs all dependencies from `pyproject.toml`
3. Verifies `config.yaml` exists
4. Checks `cameras.yaml` — if missing, runs interactive camera discovery
5. Asks about Region of Interest (full frame vs ROI zones)
6. Launches the data collection pipeline
7. Press **Ctrl+C** to stop

### Force camera re-discovery

```bash
./home_guard_project/data_collection/start.sh --discover
```

### Fresh clone on a new machine

```bash
git clone <repo-url>
cd security_camera_project
./home_guard_project/data_collection/start.sh
```

The script will guide you through camera setup (auto-discover or manual entry).

**Prerequisites:** Python >= 3.12 and Git Bash (Windows) or bash (Linux/macOS).

## Configuration

All settings live in `home_guard_project/data_collection/config.yaml`:

```yaml
output_dir: "./dataset_multi"

models:
  yolo: "yolov8n.pt"

clip:
  seconds: 10.0
  store_fps: 10.0
  store_size: null          # null = native resolution
  yolo_input_size: [960, 544]

trigger:
  score_max: 6.0
  score_reward: 3.0         # points/sec while person present
  score_penalty: 2.0        # points/sec while absent
  cooldown_sec: 5.0
  post_roll_sec: 5.0        # seconds to keep recording after trigger

random_clip:
  enabled: false
  interval_sec: 3600.0

detection:
  yolo_trigger_confidence: 0.5
  yolo_every_n_frames_cpu: 6

display:
  show_windows: true
  show_plotted_boxes: true
  save_with_plotted_boxes: false
```

Two additional YAML files (both gitignored):
- **`cameras.yaml`** — RTSP stream URLs with credentials. Generated by `discover.py`.
- **`zones.yaml`** — normalised ROI polygon vertices per camera. Generated by `roi_editor.py`.

## How It Works

### Capture

`VideoCaptureThread` reads each RTSP camera continuously in a background thread. Frames are stored at native camera resolution in a rolling buffer at `store_fps` (default 10 fps). Buffer length = `clip.seconds` + `trigger.post_roll_sec` + 2 seconds.

### Detection

YOLO runs on a **downscaled** copy of each frame (`yolo_input_size`, e.g. 960x544) for speed. The full-resolution frames are preserved in the buffer for saving.

### ROI Filtering

If a camera has a polygon defined in `zones.yaml`, only detections whose bounding-box **centre point** falls inside the polygon are counted. This lets you ignore people on public sidewalks, passing cars on roads, etc. while still saving full-frame video for labeling.

### Trigger Hysteresis

A time-based scoring system prevents spurious triggers:
- **Person detected in ROI**: score increases by `score_reward` per second
- **No person**: score decays by `score_penalty` per second
- **Trigger fires** when score reaches `score_max`
- **Cooldown**: no new triggers for `cooldown_sec` after a save

### Post-roll Recording

When the trigger fires, the system **does not save immediately**. Instead it waits `post_roll_sec` (default 5s) before grabbing the clip from the buffer. This places the triggering event in the **middle** of the saved clip (5s before + 5s after), providing context on both sides.

### Saving

The last `clip.seconds` of high-resolution frames are written as an MP4 clip (`mp4v` codec). A matching `.meta.json` records:
- Timestamps (UTC + local)
- YOLO detection summary (class counts, confidences)
- Buffer settings (FPS, resolution)
- ROI info (active/inactive, polygon coordinates)
- YOLO export manifest

### YOLO Weak-Label Export

When `yolo_export.enabled` is true, sampled frames are extracted from each saved clip and re-run through YOLO. The results are written as:
- `yolo/images/<camera>/<date>/<clip_id>_fNNNN.jpg`
- `yolo/labels/<camera>/<date>/<clip_id>_fNNNN.txt` (YOLO format: `class cx cy w h`)

These serve as weak labels for fine-tuning and as pre-annotations in Label Studio.

### Random Clips

When `random_clip.enabled` is true, the pipeline saves a clip at random intervals (with jitter) regardless of detections. Useful for collecting negative samples.

## Camera Discovery

Three strategies, tried in order:

| Strategy | How it works |
|----------|-------------|
| **ONVIF WS-Discovery** | Multicast probe finds ONVIF devices, queries Media service for RTSP URIs |
| **Subnet port scan** | Scans /24 for hosts with port 554 open, then probes common RTSP URL patterns |
| **Manual entry** | User provides NVR IP (channels auto-probed) or pastes full RTSP URLs |

Run standalone:

```bash
uv run python home_guard_project/data_collection/discover.py
```

## ROI Editor

Interactive OpenCV GUI for defining polygon zones on live camera frames.

| Control | Action |
|---------|--------|
| Left-click | Add a vertex |
| Right-click | Undo last vertex |
| `r` | Reset all vertices |
| Enter | Confirm polygon (needs >= 3 vertices) |
| Escape | Skip this camera |

Coordinates are saved as normalised (0-1) values in `zones.yaml`, making them resolution-independent.

Run standalone:

```bash
uv run python home_guard_project/data_collection/roi_editor.py
```

```
dataset_multi/
├── clips/<camera>/<YYYY-MM-DD>/<clip_id>.mp4
├── meta/<camera>/<YYYY-MM-DD>/<clip_id>.meta.json
├── responses/<camera>/<YYYY-MM-DD>/                  (empty during collection)
├── yolo/images/<camera>/<YYYY-MM-DD>/<clip_id>_fNNNN.jpg
└── yolo/labels/<camera>/<YYYY-MM-DD>/<clip_id>_fNNNN.txt
```

Clip naming: `{camera}_{unix_ts}_{trigger|random}.mp4`

This structure is consumed directly by the labeling pipeline (`home_guard_project/labeling/`).

## Display Window

When `display.show_windows` is true, a live window per camera shows:
- The current frame (downscaled to max 720px for display)
- YOLO bounding boxes (if `show_plotted_boxes` is true)
- ROI polygon overlay (semi-transparent green, if active)

Press **q** in any window to quit.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| No cameras found | Run with `--discover` or check `cameras.yaml` |
| Camera not connecting | Verify RTSP URL, check firewall, try increasing `rtsp.open_timeout_ms` |
| Too many false triggers | Define ROI zones, increase `trigger.score_max`, or decrease `score_reward` |
| Clips don't play in browser | Normal — `mp4v` codec. The labeling pipeline re-encodes to H.264 |
| High CPU usage | Increase `detection.yolo_every_n_frames_cpu`, reduce number of cameras |
| Buffer too short | Increase `clip.seconds` or `trigger.post_roll_sec` in config.yaml |
| ROI editor won't open | Needs a display (X11/Windows). Won't work over headless SSH |
