## 1. Data Sources

This project has three data pipelines that all produce the same dataset format:

### 1a. Live RTSP Capture (`data_collection/`)

Captures clips from six local RTSP cameras. YOLO runs on sub-stream frames;
when a trigger class (person/cat/dog) is detected with sustained confidence,
the system saves a 10-second clip at native resolution.

- **Output**: `dataset_multi/`
- **Clip resolution**: ~704x576 (sub-stream) or 1920x1080 (main-stream VLM crops)
- **FPS**: 7 fps (sub-stream buffer), 5 fps (VLM crops)
- **VLM text**: Empty by default (annotators fill it in Label Studio)
- **VLM crops**: Optional high-res person-focused crops (`vlm_crops/`)

### 1b. External Video Import (`video_import/`)

Imports arbitrary video files, splits them into fixed-duration chunks,
re-encodes to H.264, and runs YOLO.

- **Output**: `dataset_multi/`
- **Clip duration**: 10 seconds (configurable)
- **FPS**: 7 fps (re-encoded)
- **VLM text**: Empty (annotators fill it in Label Studio)

### 1c. UCA Dataset Import (`uca_import/`)

Imports the UCA (UCF Crime Annotation) dataset. Parses annotations that pair
timestamps with scene descriptions, splits videos at those timestamps, and
runs YOLO.

- **Source**: [Kaggle UCA/UCF Crime Annotation Dataset](https://www.kaggle.com/datasets/vigneshwar472/ucaucf-crime-annotation-dataset)
- **Output**: `dataset_uca/`
- **Clip resolution**: 320x240 (original UCF-Crime resolution, preserved as-is)
- **FPS**: 30 fps (original, preserved via stream copy -- zero quality loss)
- **VLM text**: Pre-filled from UCA annotations (human-written descriptions)
- **VLM crops**: None (full-frame only; cropping is unnecessary for training)

**Dataset scale**:

| Split | Videos | Segments | Status |
|-------|--------|----------|--------|
| UCFCrime_Test | 310 | 4,331 | Imported (4,300 clips, 1 failed, 30 skipped) |
| UCFCrime_Train | ~1,165 | 15,677 | Importing (with YOLO) |
| UCFCrime_Val | ~379 | 3,534 | Importing (with YOLO) |
| **Total** | **~1,854** | **23,542** | |

Crime categories: Abuse, Arrest, Arson, Assault, Burglary, Explosion,
Fighting, RoadAccidents, Robbery, Shooting, Shoplifting, Stealing, Vandalism,
plus Normal videos with scene descriptions.

## 2. Dataset Directory Layout

Both `dataset_multi/` and `dataset_uca/` follow the same structure:

```
dataset_root/
  clips/<camera_name>/<sub_dir>/<clip_id>.mp4
  meta/<camera_name>/<sub_dir>/<clip_id>.meta.json
  responses/<camera_name>/<sub_dir>/<clip_id>.model_raw.txt
  vlm_crops/<camera_name>/<sub_dir>/<clip_id>.mp4          (dataset_multi only)
  yolo/
    images/<camera_name>/<sub_dir>/<clip_id>_f<NNNN>.jpg
    labels/<camera_name>/<sub_dir>/<clip_id>_f<NNNN>.txt
  label_studio_config.xml      (generated by labeling pipeline)
  label_studio_tasks.json      (generated by labeling pipeline)
```

### Naming conventions

| Dataset | `camera_name` | `sub_dir` | `clip_id` example |
|---------|--------------|-----------|-------------------|
| `dataset_multi` | RTSP camera name (e.g. `main_door`) | `YYYY-MM-DD` | `main_door_1772735773_trigger` |
| `dataset_uca` | Crime category (e.g. `Abuse`) | Video stem (e.g. `Abuse039_x264`) | `Abuse_Abuse039_x264_seg000` |

### Key directories

| Path | Contents |
|------|----------|
| `clips/` | MP4 video clips (H.264 encoded, browser-playable) |
| `meta/` | `.meta.json` files with clip metadata, YOLO summary, and VLM text |
| `responses/` | `.model_raw.txt` files with raw VLM scene descriptions |
| `vlm_crops/` | Person-focused cropped video clips (only `dataset_multi`, when enabled) |
| `yolo/images/` | JPEG frames sampled from clips (for YOLO training/pre-annotation) |
| `yolo/labels/` | YOLO-format `.txt` label files (one per image) |

### VLM-related fields

```json
{
  "model_response": "A person walks through the front door carrying a bag.",
  "model_raw_text_path": "responses/main_door/2026-03-05/clip.model_raw.txt",

```

- `model_response` -- scene description text (used by labeling pipeline as pre-annotation)
- `model_raw_text_path` -- path to `.model_raw.txt` containing the same text
- `vlm_crop` -- only present when VLM crop is generated (dataset_multi with main_stream enabled)

```json
    "segment_index": 0
  }
}
```

## 4. YOLO Label Format

### File format

Each `.txt` file in `yolo/labels/` contains one detection per line:

```
<class_id> <x_center> <y_center> <width> <height>
```

All coordinates are **normalized to 0--1** relative to the image dimensions.

### Example

```
0 0.523930 0.223402 0.250735 0.251098
2 0.299716 0.143029 0.155385 0.176903
```

This means:
- Class 0 (person) centered at (52.4%, 22.3%), size 25.1% x 25.1%
- Class 2 (car) centered at (30.0%, 14.3%), size 15.5% x 17.7%

### Pre-annotation labels vs human labels

The YOLO labels in `yolo/labels/` are **machine-generated weak labels** from
YOLOv11s. They serve as pre-annotations in Label Studio. After human
correction in Label Studio, the definitive labels come from the Label Studio
export (see [Section 7](#7-exporting-annotations-from-label-studio)).

## 5. VLM Text Format

### Storage

VLM scene descriptions are stored in two places:

1. **`meta.model_response`** -- the text string inside `.meta.json`
2. **`responses/<...>/<clip_id>.model_raw.txt`** -- standalone text file

### Content

For `dataset_multi`: initially empty; annotators write descriptions in Label Studio.

For `dataset_uca`: pre-filled from the UCA annotation, e.g.:

```
A white car with double flashes slowly appeared on the screen, crushing the
black dog walking in the middle of the road.
```

### In Label Studio

The text appears as a pre-filled `<TextArea>` field. Annotators can edit,
correct, or rewrite it. The final text is exported with the annotation.

## 6. Label Studio Annotation Workflow

### What annotators see

Label Studio presents a **two-panel** layout per clip:

```
+--------------------------------------------+--------------------------------------------+
|  Full Frame -- YOLO Re-tagging             |  VLM Crop (or full frame fallback)         |
|                                            |                                            |
|  [Video player]                            |  [Video player]                            |
|  Person  Bicycle  Car  Motorcycle          |                                            |
|  Bus  Truck  Bird  Cat  Dog                |  Scene Description (for VLM training)      |
|                                            |  [Editable text area]                      |
|  [Bounding box drawing tool]               |                                            |
+--------------------------------------------+--------------------------------------------+
```

**Left panel**: Full-frame video with YOLO bounding box pre-annotations.
Annotators correct boxes (move, resize, delete, add) and assign class labels.

**Right panel**: VLM crop video (or same full-frame if no crop). Below it, a
text area with the scene description. Annotators edit or write the description.

### Annotation types collected

| Annotation | Label Studio type | `from_name` | `to_name` |
|------------|------------------|-------------|-----------|
| Bounding boxes | `VideoRectangle` | `bbox` | `video_full` |
| Class labels | `Labels` | `label` | `video_full` |
| Scene description | `TextArea` | `vlm_description` | `video_crop` |

### Available class labels

```
person, bicycle, car, motorcycle, bus, truck, bird, cat, dog
```

These map to COCO class IDs: 0, 1, 2, 3, 5, 7, 14, 15, 16.

### Launching Label Studio

```bash
# For dataset_multi (RTSP camera data)
./home_guard_project/labeling/start.sh ./dataset_multi

# For dataset_uca (UCF Crime Annotation data)
./home_guard_project/labeling/start.sh ./dataset_uca

# Force task regeneration
./home_guard_project/labeling/start.sh ./dataset_uca --force
```

### Method 1: UI export

1. Open the Label Studio project in your browser
2. Click **Export**
3. Choose **JSON** format (includes both YOLO boxes and VLM text)

### Method 2: API export


### Export JSON structure

```json
[
  {
    "id": 1,
    "data": {
      "video_url": "http://...",
      "meta_path": "meta/Abuse/Abuse039_x264/Abuse_Abuse039_x264_seg000.meta.json",
      "camera_name": "Abuse",
      "kind": "uca_import",
      "duration_sec": 7.5,
      "fps": 30.0
    },
    "annotations": [
      {
        "result": [
          {
            "type": "videorectangle",
            "from_name": "bbox",
            "to_name": "video_full",
            "value": {
              "sequence": [
                {
                  "frame": 1,
                  "time": 0.0,
                  "x": 10.5,
                  "y": 25.3,
                  "width": 15.2,
                  "height": 30.1,
                  "enabled": true,
                  "rotation": 0
                }
              ]
            }
          },
          {
            "type": "labels",
            "from_name": "label",
            "to_name": "video_full",
            "value": {
              "labels": ["person"],
              "sequence": [...]
            }
          },
          {
            "type": "textarea",
            "from_name": "vlm_description",
            "to_name": "video_crop",
            "value": {
              "text": ["A person enters through the front door carrying a bag."]
            }
          }
        ]
      }
    ]
  }
]
```

### Key fields for training

| What you need | Where to find it |
|---------------|-----------------|
| YOLO boxes | `annotations[].result[]` where `type == "videorectangle"` |
| Class labels | `annotations[].result[]` where `type == "labels"`, field `value.labels` |
| VLM text | `annotations[].result[]` where `type == "textarea"`, field `value.text[0]` |
| Video path | `data.meta_path` -> read the `.meta.json` -> `clip_path` |
| Video FPS | `data.fps` |
| Original clip | `data.meta_path` -> `.meta.json` -> `clip_path` |

### Label Studio coordinate system

Bounding boxes use **percentage coordinates (0--100)**:

- `x`, `y` = top-left corner as percentage of frame width/height
- `width`, `height` = box size as percentage of frame width/height

Convert to YOLO normalized (0--1) format:

```python
# Label Studio (0-100) -> YOLO (0-1)
xc = (x + width / 2) / 100.0
yc = (y + height / 2) / 100.0
w  = width / 100.0
h  = height / 100.0
```

### 8b. The analysis pipeline (`home_guard_project/analysis/`)

This pipeline takes a Label Studio JSON export and produces all training
artifacts in one command:

```bash
# Download the export JSON from S3 first (or export from Label Studio UI)
# Then run the analysis:
py -m home_guard_project.analysis path/to/export.json [--output-dir ./analysis_output]
```

It produces four outputs:

1. **`summary_report.md`** -- annotation statistics, quality flags, per-camera breakdown
2. **`analysis.xlsx`** -- Excel workbook with task-level and track-level sheets
3. **`yolo/data.yaml` + `yolo/labels/`** -- YOLO training labels with keyframe interpolation
4. **`vlm_training.jsonl`** -- VLM fine-tuning data

CLI flags:

```
py -m home_guard_project.analysis EXPORT.json [OPTIONS]

  --output-dir DIR    Output directory (default: ./analysis_output)
  --no-report         Skip summary report
  --no-excel          Skip Excel workbook
  --no-yolo           Skip YOLO training data
  --no-vlm            Skip VLM JSONL
```

### 8c. How YOLO labels are extracted

The analysis pipeline (`analyze.py` -> `write_yolo_labels()`) does:

1. Reads each `videorectangle` annotation with its `value.labels` (e.g. `["person"]`)
2. **Interpolates** between keyframes to produce a bounding box for every
   frame (not just keyframe frames), using linear interpolation from
   `utils/ls_convert.py:interpolate_keyframes()`
3. Converts Label Studio percentage coords (0--100) to YOLO normalized (0--1)
   using `ls_rect_to_yolo()`
4. **Remaps** COCO IDs to contiguous 0..N-1 (e.g. COCO 0 -> 0, COCO 2 -> 2,
   COCO 5 -> 4, etc.)
5. Writes one `.txt` per frame: `{clip_id}_f{NNNN}.txt`
6. Generates `data.yaml` for Ultralytics

The output structure:

```
analysis_output/yolo/
  data.yaml
  labels/
    front_side/2026-02-21/front_side_1771696865_trigger_f0001.txt
    front_side/2026-02-21/front_side_1771696865_trigger_f0002.txt
    ...
```

**`data.yaml`** (auto-generated):

```yaml
path: /absolute/path/to/analysis_output/yolo
train: labels
val: labels
names:
  0: person
  1: bicycle
  2: car
  3: motorcycle
  4: bus
  5: truck
  6: bird
  7: cat
  8: dog
nc: 9
```

**Note**: The generated `data.yaml` points `train` and `val` both at `labels/`.
For actual training, you need to split into train/val (see Section 9a).

**Note**: The `yolo/labels/` from the analysis pipeline are **human-corrected**
labels (from Label Studio annotations). The `dataset_multi/yolo/labels/` are
**machine-generated** weak labels (from YOLO pre-annotation). Use the
analysis-output labels for training.

### 8d. How VLM data is extracted

The analysis pipeline (`analyze.py` -> `write_vlm_jsonl()`) writes one JSON
line per task to `vlm_training.jsonl`:

```json
{
  "video_s3_path": "s3://security-camera-project-v1/dataset_multi/clips/front_side/2026-02-21/front_side_1771696897_trigger.mp4",
  "vlm_crop_s3_path": "s3://security-camera-project-v1/dataset_multi/vlm_crops/front_side/2026-02-21/front_side_1771696897_trigger.mp4",
  "description": "Two individuals are standing next to each other, appearing to look down at something while engaging in conversation.",
  "camera_name": "front_side",
  "duration_sec": 9.8,
  "num_persons": 1,
  "num_cars": 2,
  "kind": "trigger",
  "date": "2026-02-21",
  "clip_id": "front_side_1771696897_trigger"
}
```

Each record includes:
- `video_s3_path` -- S3 URI for the full-frame clip
- `vlm_crop_s3_path` -- S3 URI for the person-focused VLM crop
- `description` -- the human-written scene description from Label Studio
- Metadata fields (`camera_name`, `duration_sec`, `num_persons`, etc.)

### 8e. Annotation structure in the export JSON

In the Label Studio export, each `videorectangle` result contains **both** the
bbox geometry and the class labels within the same object:

```json
{
  "id": "bbox_0",
  "type": "videorectangle",
  "from_name": "bbox",
  "to_name": "video_full",
  "value": {
    "labels": ["person"],
    "framesCount": 61,
    "duration": 8.71,
    "sequence": [
      {
        "frame": 1, "time": 0.0,
        "x": 19.2, "y": 14.4, "width": 12.5, "height": 30.1,
        "enabled": true, "rotation": 0
      }
    ]
  }
}
```

Key details:
- `value.labels` -- class labels are embedded inside the videorectangle (not as separate `labels` results)
- `value.sequence` -- keyframes with bbox coords in Label Studio % (0--100)
- `value.framesCount` / `value.duration` -- total frames / duration of the video
- `enabled: false` on a keyframe means the object is occluded/not visible at that frame

The VLM text is a separate `textarea` result:

```json
{
  "type": "textarea",
  "from_name": "vlm_description",
  "to_name": "video_crop",
  "value": { "text": ["A person walks through the front door carrying a bag."] }
}
```

## 9. Fine-Tuning YOLO

### 9a. Prepare the dataset

The analysis pipeline (Section 8b) already produces YOLO labels with remapped
class IDs and a `data.yaml`. The existing batch 1 labels are at:

```
s3://security-camera-project-v1/tagging/ameer_house_batch_1/analysis_output/yolo/
```

YOLO training expects images and labels in parallel directories. The images
come from the dataset's `yolo/images/` directory. To build a training dataset:

1. **Download human-corrected labels** from S3 `analysis_output/yolo/labels/`
2. **Download images** from S3 `dataset_multi/yolo/images/`
3. **Split into train/val** (80/20 by clip to avoid data leakage)
4. **Arrange** into the Ultralytics directory structure:

```
yolo_dataset/
  images/
    train/
      front_side_1771696865_trigger_f0001.jpg
      ...
    val/
      main_door_1771696897_trigger_f0001.jpg
      ...
  labels/
    train/
      front_side_1771696865_trigger_f0001.txt
      ...
    val/
      main_door_1771696897_trigger_f0001.txt
      ...
  data.yaml
```

**`data.yaml`** (generated by the analysis pipeline, adjust paths):

```yaml
path: /path/to/yolo_dataset
train: images/train
val: images/val
nc: 9
names:
  0: person
  1: bicycle
  2: car
  3: motorcycle
  4: bus
  5: truck
  6: bird
  7: cat
  8: dog
```

**Class ID remapping**: The analysis pipeline already remaps sparse COCO IDs
(0, 1, 2, 3, 5, 7, 14, 15, 16) to contiguous IDs (0--8) in the label files.
No manual remapping is needed when using `analysis_output/yolo/labels/`.

| Original COCO ID | Training ID | Label |
|:-:|:-:|:--|
| 0 | 0 | person |
| 1 | 1 | bicycle |
| 2 | 2 | car |
| 3 | 3 | motorcycle |
| 5 | 4 | bus |
| 7 | 5 | truck |
| 14 | 6 | bird |
| 15 | 7 | cat |
| 16 | 8 | dog |

### 9b. Two types of YOLO labels

| Source | Location | Quality | Class IDs |
|--------|----------|---------|-----------|
| Machine-generated (weak) | `dataset_multi/yolo/labels/` | Pre-annotation from YOLOv11s, not human-verified | Original COCO (0, 2, 5, 7...) |
| Human-corrected | `analysis_output/yolo/labels/` | Corrected by annotators in Label Studio, interpolated | Remapped contiguous (0--8) |

Always prefer the human-corrected labels from the analysis pipeline for
training. The machine-generated labels are useful for pre-annotation only.

### 9c. Training command

```bash
yolo detect train \
  data=yolo_dataset/data.yaml \
  model=yolo11s.pt \
  epochs=100 \
  imgsz=640 \
  batch=16 \
  project=runs/detect \
  name=homeguard_v1
```

Key parameters:

| Parameter | Recommended | Notes |
|-----------|-------------|-------|
| `model` | `yolo11s.pt` | Same model used for pre-annotation; fine-tune from it |
| `imgsz` | `640` | Matches the detection pipeline input size |
| `batch` | 16 | Adjust for GPU memory |
| `epochs` | 100--300 | Monitor val mAP; use early stopping |
| `lr0` | 0.01 | Default; reduce to 0.001 for fine-tuning |
| `patience` | 20 | Early stopping patience |

### 9d. Validation

```bash
yolo detect val \
  data=yolo_dataset/data.yaml \
  model=runs/detect/homeguard_v1/weights/best.pt \
  imgsz=640
```

### 9e. Using the fine-tuned model

Update the pipeline configs to use the trained model:

## 10. Fine-Tuning Qwen 2.5 VL

### 10a. Training data format

Qwen 2.5 VL expects conversation-style training data. Each sample pairs
a video with a text description:

```json
[
  {
    "id": "Abuse_Abuse039_x264_seg000",
    "conversations": [
      {
        "from": "human",
        "value": "<video>\nDescribe what happens in this surveillance video."
      },
      {
        "from": "assistant",
        "value": "The yellow-haired woman walked behind the black-haired woman, and the man in black walked to the blue door."
      }
    ],
    "video": "/path/to/clips/Abuse/Abuse039_x264/Abuse_Abuse039_x264_seg000.mp4"
  }
]
```

### 10b. Preparing the training JSONL

The analysis pipeline already produces `vlm_training.jsonl` (see Section 8d).
The existing batch 1 data is at:

```
s3://security-camera-project-v1/tagging/ameer_house_batch_1/analysis_output/vlm_training.jsonl
```

Each line contains:

```json
{
  "video_s3_path": "s3://security-camera-project-v1/dataset_multi/clips/front_side/2026-02-21/front_side_1771696897_trigger.mp4",
  "vlm_crop_s3_path": "s3://security-camera-project-v1/dataset_multi/vlm_crops/front_side/2026-02-21/front_side_1771696897_trigger.mp4",
  "description": "Two individuals are standing next to each other...",
  "camera_name": "front_side",
  "duration_sec": 9.8,
  "num_persons": 1,
  "num_cars": 2,
  "kind": "trigger",
  "date": "2026-02-21",
  "clip_id": "front_side_1771696897_trigger"
}
```

To convert this into Qwen 2.5 VL training format, download the videos from
S3 and transform the JSONL:

```python
import json

samples = []
with open("vlm_training.jsonl") as f:
    for line in f:
        rec = json.loads(line)
        if not rec["description"].strip():
            continue

        # Use vlm_crop if available (person-focused), else full-frame
        video_path = f"videos/{rec['clip_id']}.mp4"

        samples.append({
            "id": rec["clip_id"],
            "conversations": [
                {
                    "from": "human",
                    "value": "<video>\nDescribe what happens in this surveillance video."
                },
                {
                    "from": "assistant",
                    "value": rec["description"],
                },
            ],
            "video": video_path,
        })

with open("vlm_train.json", "w") as f:
    json.dump(samples, f, indent=2, ensure_ascii=False)
```

For UCA dataset clips (which have no VLM crops), extract directly from
the metadata:

```python
import json, glob

samples = []
for meta_path in glob.glob("dataset_uca/meta/**/*.meta.json", recursive=True):
    with open(meta_path) as f:
        meta = json.load(f)
    description = meta.get("model_response", "").strip()
    if not description:
        continue
    clip_path = meta["clip_path"]
    clip_id = os.path.splitext(os.path.basename(clip_path))[0]
    samples.append({
        "id": clip_id,
        "conversations": [
            {"from": "human", "value": "<video>\nDescribe what happens in this surveillance video."},
            {"from": "assistant", "value": description},
        ],
        "video": os.path.join("dataset_uca", clip_path),
    })
```

### 10e. Key hyperparameters

| Parameter | Recommended | Notes |
|-----------|-------------|-------|
| `finetuning_type` | `lora` | LoRA is practical for 7B+ models on consumer GPUs |
| `lora_rank` | 64 | Higher rank = more capacity; 32--128 typical |
| `learning_rate` | 1e-5 | Conservative for fine-tuning |
| `num_train_epochs` | 2--5 | Monitor eval loss |
| `video_fps` | 2.0 | Sample rate for video frames fed to VLM |
| `video_maxlen` | 64 | Max frames per video |
| `max_pixels` | 200704 | ~448x448; increase for better quality |
| `per_device_train_batch_size` | 1 | Video is memory-heavy; compensate with gradient accumulation |

### 10f. Inference after fine-tuning

```python
from transformers import Qwen2_5_VLForConditionalGeneration, AutoProcessor

model = Qwen2_5_VLForConditionalGeneration.from_pretrained(
    "runs/qwen25vl_homeguard",
    torch_dtype="auto",
    device_map="auto",
)
processor = AutoProcessor.from_pretrained("runs/qwen25vl_homeguard")

messages = [
    {
        "role": "user",
        "content": [
            {"type": "video", "video": "path/to/clip.mp4", "fps": 2.0},
            {"type": "text", "text": "Describe what happens in this surveillance video."},
        ],
    }
]

text = processor.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = processor(text=[text], videos=["path/to/clip.mp4"], return_tensors="pt").to(model.device)
output = model.generate(**inputs, max_new_tokens=256)
print(processor.decode(output[0], skip_special_tokens=True))
```
