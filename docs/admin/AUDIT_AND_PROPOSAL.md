### A4. Can a browser draw YOLO boxes over saved video?

| Surface | Answer today | Browser requirement / limitation |
|---|---|---|
| Production alerts, including inference training copies | **No saved per-frame boxes.** `yolo.class_counts` is presence-only, one per distinct label, not actual object counts. Live normalized boxes exist only in overwritten status. [`box/alert_clips.py:199-200`; `box/ai_status.py:65-73`; `box/inference.py:952-954`] | Past capture-time boxes cannot be recovered from summaries. Either add capture-time detection sidecars, or rerun detector in cloud and label results **recomputed**, with its own model/version. Latest status cannot be joined reliably to historical video. |
| Collection default export | **Sampled-frame boxes, not every saved frame and not the original online detector trace.** Export reruns YOLO on stored frames. Current YAML requests 3 fps, store fps 7; step is `round(7/3)=2`, so nominal sampling is every second frame, not exactly 3 fps. `.txt` omits confidence and tracking. [`data_collection/config.yaml:15,55-61`; `data_collection/data_collection.py:288-323`] | Read `frame_index` and paired labels; map normalized center-size to `(xc−w/2,yc−h/2,xc+w/2,yc+h/2)`, scale to displayed video content rectangle. Prefer `frame_index / actual encoded fps`; `approx_time_offset_sec` uses configured store fps and may drift from `fps_estimated`. No boxes on unsampled frames unless explicitly interpolated/recomputed. [`data_collection/data_collection.py:305-323,1103-1105,1125-1131`] |
| Collection `save_with_plotted_boxes` | Optional rerun on **every** saved frame and burned-in visualization; default YAML false. Does not create a reversible box trajectory. [`data_collection/data_collection.py:1096-1105`; `data_collection/config.yaml:109`] | Burned-in boxes are already pixels; cannot toggle/filter them. Enabling this adds detector work and is unsuitable as the default N150 admin solution. |
| High-resolution crop videos | `per_frame_tracking:true` describes crop generation, not saved object tracks. Only first crop rectangle survives. [`data_collection/data_collection.py:944-1008,1050-1067`] | To project full-frame detections onto these videos, persist each output frame's crop/resize transform and alignment to source frame; otherwise overlay on original substream only. |

## Part B — Proposal (new design, not existing behavior)

### B1. Decision: hybrid, with cloud as the history/control record

| Option | History / training | Live / owner view | Config / model changes | Assessment |
|---|---|---|---|---|
| Cloud-first: S3 + small index DB; desired/reported documents | Available while box offline; efficient cross-fleet search and exports | Periodic uploads are not live; continuously uploading preview is costly and privacy-sensitive | Box polls desired state; asynchronous and resilient to offline periods | Best backbone; alone does not satisfy on-demand live view |
| Direct-to-box API over Tailscale | Depends on connectivity, local retention, and per-box disk scans; training clips may already be uploaded/deleted | Best path to current preview and local state | Immediate requests possible, but require acknowledgment, concurrency control, rollback | Useful support transport; insufficient as fleet source of truth |
| **Hybrid** | S3 media + Postgres index; independent feedback and AI records | Short-lived backend gateway session to existing/extended loopback API over Tailscale | One desired/reported protocol; direct channel may wake reconciliation, never bypass it | **Recommended**: history works offline, live is deliberate, boxes remain autonomous |

Do not wait for a new video stack, assistant v2, or universal device-management service to ship phase 1. Do not build a second detector or a local admin database on each box.

### B2. Components and data ownership

| Component | Responsibility / boundary |
|---|---|
| Admin web app + backend | Customer/device inventory, health with freshness, event timeline, player + overlay, AI/owner conversation, exports, configuration diff, deployment status. Staff SSO/MFA; tenant authorization on every resource. Browser receives no RTSP URLs, SSH keys, bot tokens, or box AWS credentials. |
| Postgres + index worker | Primary metadata query layer. Initial bounded scan of authorized legacy prefixes; thereafter incremental discovery plus retry/reconciliation. Preserve raw JSON revisions and unknown fields. S3 remains media store; DB is not a replacement for retained video. |
| Object storage | Keep legacy prefixes readable. New immutable event assets/records under `fleet/<device_id>/<assignment_id>/events/<event_id>/...`; separate explicit operational/training retention. Desired and reported state outside `production_`. No recursive customer-wide listing per page load. |
| Media worker | Cloud thumbnails, browser-compatible renditions, optional recomputed detections, export packaging/redaction. Preserve original bytes and rendition mapping; queue work, do not burden N150. |
| Tailscale gateway | Backend-managed tunnel to allowlisted device/loopback service. One bounded viewer lease per box initially, fan out same preview to authorized viewers. Short session TTL, access audit, no arbitrary SSH command input. No need for staff browser to join tailnet. |
| Box publisher/reconciler | Lightweight I/O worker alongside runner: serialize already computed detections, upload completed manifests, publish reported state, poll desired state. Bounded queue/disk spool, exponential backoff + jitter, no dependency of alert loop on admin/cloud availability. |
| Release store + deployment worker | Immutable signed release manifests, weights/prompts with SHA-256, compatibility constraints, rollout cohorts, canary gates, rollback accounting. Separate signing/deployment authority from device credentials. |
| Telegram ingress (fleet prerequisite) | Choose one bot per household as quickest isolation, or implement one central ingress that durably routes updates by tenant/chat to box. Do not run independent shared-token pollers fleet-wide. |

### B3. Data model

Use UUIDs for new entities; keep legacy `site`, camera names, stems and original keys as aliases. Device identity survives replacement of a site's display name; a new household assignment must not inherit old household access.

| `chat_messages`, `tool_receipts` | message/turn IDs, customer/chat pseudonym, speaker role, text, media/event refs, delivery per recipient, timestamps; tool name/args/result/status and idempotency key. Full raw audit restricted; redacted display default |
| `device_state`, `health_samples` | desired generation, reported generation/config hash, local revision, update result, release IDs, last seen; historical sample with engine progress, camera frame ages, disk, queue bytes/age, errors |
| `config_revisions` | assignment, revision/generation, base reported hash, validated settings/cameras/zones, author/reason, created/expiry, apply state; immutable versions |
| `releases`, `deployments`, `deployment_devices` | signed manifest, compatible engine/schema/hardware, hashes, eval record; target cohort, previous release, per-device phase/errors/rollback, author |
| `consent_grants`, `access_sessions`, `audit_log` | purpose/cameras/media categories, granted/revoked/expiry, policy version; staff reason/session lease; append-only read/export/config/deploy events |
| `exports`, `export_items` | request/filter snapshot, approved purpose, versions/hashes, dataset split, labels/provenance, status/expiry, requester; immutable manifest and downloadable package |

Indexes: `(customer_id,camera_id,start_ts DESC,event_id)` and `(customer_id,start_ts DESC,event_id)` for cursor paging; filtered label/kind/verdict indexes; full-text summaries initially. Add multilingual semantic search later on filtered candidates. Large frame trajectories stay in compressed sidecars, not millions of DB rows. Target p95 <500 ms for a 100-event metadata page on a representative indexed corpus; measure before promising it.

Legacy ingest rules: normalize `\\` to `/`; reject absolute/traversal/cross-tenant refs; parse raw timestamps without deriving time from filenames when fields exist; distinguish missing versus empty values. Group production/training copies as one event with separate artifacts, never erase their differing metadata. Save raw revisions before merging. Index standalone feedback even if video is gone, and orphan assets as incomplete. Expose completeness badges: `video`, `sampled boxes`, `capture boxes unavailable`, `teacher`, `owner feedback`, `expired`.

### B4. Box publication contract

These are new files/contracts. Extend explicit staging allowlists; do not widen current upload roots.

| Local file / cloud object | Fields and publication rule |
|---|---|
| Event `manifest.json` → immutable `.../events/<event_id>/revisions/<n>/manifest.json` | `schema_version,event_id,device_id,assignment_id,camera_id,kind,mode,start/end/trigger_ts,timezone,config_revision,zone_revision,model_release_ids,artifacts:[{role,key,sha256,bytes,mime,frame_count,...}],capture_complete,created_at`. Finish all writers; upload/verify assets; publish manifest **last**. Each amendment is a new revision. Manifest is visibility barrier, not `.meta.json` presence. |
| `detections.ndjson.gz` + `frame_map.json.gz` | Header: schema, class map, model hash, source/output dimensions, coordinate convention. Detection rows: `source_frame_id,capture_ts,detected_at,boxes:[{class_id,label,confidence,xyxy_norm,track_id?}]`. Frame map: `output_frame_index,pts_ms,source_frame_id,capture_ts,detection_ref\|null,status`. Include crop/resize transform for each crop-rendition frame. `status=not_run` is distinct from `ran_empty`; bounded, explicitly marked carry/interpolation for display only. |
| `ai/<run_id>.json` + referenced inputs/raw text | Exact call purpose, model/prompt/schema versions + hash, request/input refs, raw and parsed response, exception/refusal, timings and usage. Journal failures too. Guard, assistant, live-look, and later reanalysis each get distinct runs; reanalysis never overwrites original answer. |
| `feedback/<feedback_id>.json`, `chat/<segment_id>.jsonl`, `receipts/<segment_id>.jsonl` | Immutable append records with IDs, event/turn associations, timestamps, explicit per-recipient delivery result. | `logs/admin/reported.json` → `fleet/<device_id>/state/reported.json` | Contract below; atomically replace locally, publish on change and every ~60 seconds with jitter. Include assignment to reject delayed reports from old tenant. Persist history centrally. |
| `logs/admin/apply/<command_id>.json` → `.../state/results/<command_id>.json` | Durable apply receipt written before reporting success; current/previous release, generations/hashes, phase, timestamps, errors, rollback outcome. Keep terminal results centrally. |
| `logs/admin/upload-journal` (local only) | Artifact hash, key, manifest state, attempts, ack, pending bytes/age. Bounded spool with explicit retention/drop policy and telemetry. Never delete unacknowledged evidence silently to make queue look healthy. |

Serialize the detector's existing results and frame identity; **do not run extra YOLO to populate every frame**. For collection exports, retain their “recomputed weak labels” provenance. Optional dense labels are a cloud job. If disk pressure forces loss, report gaps and prioritize guard operation; do not block camera readers on upload/compression.

### B5. Desired/reported state and configuration application

| Document | Required contract |
|---|---|
| Desired: `fleet/<device_id>/state/desired.json` | `schema_version,device_id,assignment_id,generation,command_id,issued_at,expires_at,base_reported_config_hash,base_local_revision,author_ref,reason,config:{mode,alert_settings,cameras,zones},releases:{yolo,guard_vlm,assistant,live_vision},apply_policy:{not_before,window,health_timeout,rollback_to},signature`. Use camera/credential references; no plaintext secrets or arbitrary shell. Immutable generation copy plus latest pointer. |
| Reported | `schema_version,device_id,assignment_id,boot_id,sequence,reported_at,engine_version,capabilities,desired_generation_seen,applied_generation,local_revision,effective_config,effective_config_hash,active_release_ids,previous_release_ids,apply:{command_id,phase,error_code,message},health:{engine_progress_ts,cameras:[{id,last_frame_ts,last_detection_ts,enabled,muted_until,stream_state}],disk_free,upload_pending_bytes,oldest_pending_ts,last_upload_success,vlm_errors,notification_errors},clock_offset_estimate`. All content allowlisted/redacted. |

Apply phases: `received → validated → downloading → staged → applying → verifying → applied`, or `rejected/failed/rolled_back`. A received generation is never shown as applied. Direct “apply now” only wakes the same reconciler.

Rules:

1. Backend serializes writes per device and checks caller's base revision (`409` on conflict). Device rejects wrong assignment, stale generation, expired command, incompatible schema/capability, invalid zones/types, or unexpected current config hash. Poll ~30–60 seconds with jitter/backoff; offline keeps last known good state.
2. Local owner/app/assistant changes remain allowed, increment local revision and publish drift. Do not repeatedly reapply an old desired generation over them. Staff rebases a new command on reported state. An owner stop/pause survives reconciliation and model maintenance.
3. Validate whole batch, prepare temporary files and rollback copies, then apply as one config revision through shared validators. Live-only changes publish applied state after engine acknowledgment; camera/zone/mode/model changes coalesce into **one** restart. A local journal recovers interrupted multi-file commits.
4. Split secrets from ordinary config: enrollment-scoped device identity; protected local credential store; encrypted one-use provisioning envelope if remote rotation is needed. Report only configured/validity/version, never secret value. Device can read only its desired state and authorized release artifacts; write only its own reports/events/results. Staff backend uses separate scoped credentials.
5. Do not include network/Tailscale/SSH changes in ordinary configuration rollout. Device/site reassignment is a separate workflow: revoke old grants, stop old assignment, account for pending uploads, clear household state/keys, enroll new assignment, verify isolation.

### B6. Safe model update and rollback

| Stage | Required behavior |
|---|---|
| Build/release | Immutable manifest pins YOLO bytes + SHA-256 + class map/input format, guard prompt text/hash + response schema + provider model, assistant/live prompts/models, minimum engine/dependency versions and N150 compatibility. Signed by release authority. Prompt version is human-readable plus content hash. No floating git branch or provider model assumption as artifact identity. |
| Validate/canary | Run masked capture-input replay for guard, detection accuracy/latency tests, JSON compatibility, and assistant tool/receipt evaluations for affected component. Test on one household with consent; compare alert volume/error rate and CPU/frame freshness with baseline before cohort expansion. |
| Stage without interruption | Download to a separate immutable version directory at low I/O priority; resume/retry, verify signature/hash/size/free space. Keep active and previous release. For prompt/model-only update, stage text/schema/provider configuration; no local VLM weights on N150. |
| Activate | Journal old config/release first. Quiesce/finalize pending clips within a bounded window, stop worker, atomically switch active pointer/config, restart once. Do not load two YOLO models concurrently on this CPU. Run a bounded known-frame warmup and schema checks. Preserve secrets, cameras, masks, owner stop/pause. |
| Prove health | Separate lightweight supervisor watches startup deadline, crash loop, progressing decoded-frame timestamps and detector progress during configured hours, resource bounds, and AI schema compatibility. Camera/internet outage alone is not proof that the new weights failed. Provider check is limited and sends no customer image unless consent permits it. Report applied only after successful health window. |
| Roll back | Supervisor outside detector process restores previous pointer/config if candidate cannot load, crashes, violates compatibility or degrades operation beyond threshold. Report reason and rollback receipt; quarantine failed generation so repeated polling cannot reinstall it. Resume pending uploads with their original model provenance. |
| Fleet rollout | Founder/home canary → small cohort → wider fleet. Automatic pause for error/rollback thresholds; manual rollback creates a new desired generation referencing previous approved release. Offline boxes remain queued and honor expiry/maintenance window on reconnect. |

Engine code updates need the same pinned package + health/rollback discipline in a later phase. Until then, model manifests must reject features requiring a newer engine; do not smuggle executable code through a “prompt/model” update.

### B7. API surface

All public routes authorize by tenant and capability, return source timestamp/completeness, and audit sensitive reads. Mutation routes require idempotency key and expected revision; asynchronous work returns job/command ID.

| Admin backend route | Contract |
|---|---|
| `GET /customers`, `/devices`, `/devices/{id}` | Customer/fleet inventory, assignment, latest health with age, pending config/deployment |
| `GET /devices/{id}/state`, `/health?from=&to=` | Desired vs reported diff; health samples and explicit stale/offline/unknown states |
| `GET /events?customer=&camera=&from=&to=&kind=&label=&verdict=&cursor=` | Indexed, cursor-paged history; never lists S3 synchronously per request |

An always-on tailnet-bound service requires explicit device authentication and tailnet ACLs; it is not a bind-address change alone.

### B9. CPU, privacy, and rollout order

| Constraint | Product/design requirement |
|---|---|
| N150 budget | Keep YOLO thread cap; no extra RTSP session for admin preview, no dense detector rerun, no permanent live stream. Serialize existing results via bounded queue; upload compressed batches, not per-frame requests. Coalesce state writes; instrument publisher CPU, frame freshness, queue pressure. Start with one selected camera at 1–2 fps and shared existing preview; higher rate only after device measurements. |
| Household consent | Separate permissions for service recording/cloud upload, staff live access, recorded-video review, chat review, and training/export. Scope by camera, purpose and time; default staff live access off. Explain retained training copies separately from operational retention. These are product requirements; legal wording/retention obligations need jurisdiction-specific review before launch. |
| Staff visibility | Owner-authorized session or explicit standing support grant, recorded reason/ticket, visible access history and revocation. Staff role separation: support view, training export, configuration, deployment. Log media reads/downloads, not just login and mutations. No silent unattended fleet camera wall. |
| Masking | Normal admin view mirrors masked owner pipeline. Unmasked setup image requires separate narrow permission and short retention. Reject invalid remotely edited zones; report zone failure explicitly. Training transformations must preserve consented boundaries. |
| Privacy lifecycle | Encryption/access control, short URL/session TTLs, audit retention, revoke access promptly; cascade deletion to thumbnails, exports, indexes and AI/chat text where policy requires. Staff UI renders AI/owner text as untrusted content. |

| Phase | Deliverable / order | Acceptance criterion |
|---|---|---|
| **1 — usable in 2–4 engineering days** | Read-only web console, manually enrolled customer/site registry, S3 metadata/feedback index, fleet heartbeat view, filtered timeline/player, teacher-answer/feedback inspection, selected-event export. Use already-authorized read access when implementation begins; this proposal performs no cloud action. Review training access/retention grants first. | Browse one customer across both prefixes quickly, deduplicate copies, view available video/teacher answer, export existing artifacts. Show heartbeat age and schema/media gaps honestly. No promise of legacy production overlays, full chat, live, or config writes. |
| **2 — owner view + reliable publication** | Tailscale gateway to existing `serve.py` with access leases and stale-image checks; extend box frame IDs/detection sidecars, manifest completion, immutable AI/feedback/chat ledger, reported health. | **3 — configuration control** | Device enrollment and scoped permissions, desired/reported reconciler, config revisions/validation, live apply and single-restart batches, owner-change conflicts, receipts. Implementation exit checks should use fixtures for every schema above, including late feedback, same-size metadata edits, missing teacher, orphan video, stale preview, renamed camera, duplicate copies and expired media. This audit ran no application tests or external checks; proposed timings and acceptance criteria are planning targets.
